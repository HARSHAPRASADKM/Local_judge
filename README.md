# LocalJudge — personalized coding practice

HTML/CSS/JS + Spring Boot + MySQL. Problems are generated by **Ollama on your PC** ($0 API). Java and Python only.

## Requirements

- JDK 17+
- Maven 3.9+
- MySQL 8 (or Docker)
- [Ollama](https://ollama.com) with a coder model pulled
- Optional: Docker Desktop for isolated judging (falls back to local `python` / `javac` if Docker is not running)

## One-time setup

```bash
docker compose up -d
```

```bash
ollama pull qwen2.5-coder:1.5b
```

Pick a model matched to your machine. Set `app.ollama.model` in `src/main/resources/application.yml`:

- **8 GB RAM or a CPU-only laptop:** `qwen2.5-coder:1.5b` (default, ~1 GB) or `qwen2.5-coder:3b` (~2 GB).
- **16 GB RAM:** `qwen2.5-coder:7b` (~4.7 GB).
- **More RAM / a GPU:** `qwen2.5-coder:14b` or `llama3.1:8b`.

Smaller models are faster but fail the generated-test self-check more often — just generate again.

Default MySQL: `root` / `root`, database `practice`.

## Run

```bash
mvn spring-boot:run
```

Open http://localhost:8080 — register, generate a problem, then Run (public tests) vs Submit (all tests). Failed submits cannot be accepted. After 3 consecutive failed submits, **Ask hint** works on the same page.

Keep **Ollama running** while generating or requesting hints. If it is down, the API tells you to start it.

## Judge

Preferred: Docker images `python:3.12-slim` and `eclipse-temurin:17-jdk` (`--network none`, memory/CPU limits).

Fallback: host Python and JDK on PATH, with a process timeout.

Programs must read **stdin** and write **stdout**. Generated problems are stored only after the AI reference solution passes every generated test (one automatic regenerate on failure).

## Troubleshooting: "Generate" adds no new problem

Every problem comes from the local model — there is no built-in problem bank. If nothing new
shows up on the Problems page, generation failed *before* saving. Check in order:

1. **Is Ollama running?** The app talks to `http://127.0.0.1:11434`. Start it with `ollama serve`
   and leave it running while you generate.
2. **Is the model pulled?** Run `ollama list` and confirm the model named in `app.ollama.model`
   (default `qwen2.5-coder:7b`) appears. If not: `ollama pull qwen2.5-coder:7b`.
3. **What does the app think?** Open `/generate.html` — a red banner appears at the top when
   Ollama is unreachable or the model is missing, and the Generate button is disabled. The same
   status is exposed by `GET /api/ai/health`.
4. **Still failing?** A problem is saved only after the AI's own reference solution passes every
   test it generated. If the model keeps returning broken tests, the request fails with a
   self-check message — just generate again. Each request uses a fresh random seed, and the prompt
   lists your existing problems so it avoids repeating them.
